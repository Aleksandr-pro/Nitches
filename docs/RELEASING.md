# Как выпускать APK (с телефона)

## Быстрый путь — артефакт сборки (без публичного релиза)

1. GitHub → **Actions** → **Build Android APK** → **Run workflow** (ветка `main`).
2. Дождаться зелёного завершения (~5–10 мин).
3. Открыть запуск → раздел **Artifacts** → `NitchesHorizon-apk` — внутри подписанный APK.
   Артефакт живёт 90 дней и требует входа в GitHub.

## Публичный релиз (страница Releases + прямая ссылка на APK)

В репозитории действуют **immutable releases**: в уже опубликованный
релиз нельзя догрузить файлы, а имя тега, использованное опубликованным
релизом, нельзя использовать повторно никогда (тег `v0.6.0` так сгорел —
поэтому публичная серия продолжится с `v0.6.1`). Правильный порядок —
сначала ЧЕРНОВИК, потом CI, потом публикация:

1. Версия в `package.json` должна совпадать с будущим тегом (`0.6.1` ↔ `v0.6.1`) —
   это делает агент/PR до релиза.
2. GitHub → **Releases** → **Draft a new release** → в поле тега ввести новый,
   например `v0.6.1` (GitHub предложит создать тег при публикации) →
   **Save draft**. ⚠️ Не нажимать Publish на этом шаге!
3. GitHub → **Actions** → **Build Android APK** → **Run workflow**:
   - `publish_to_release` = ✅ true
   - `release_tag` = `v0.6.1`
4. Дождаться зелёного завершения: CI соберёт и подпишет APK и догрузит его
   в черновик релиза.
5. GitHub → **Releases** → открыть черновик → проверить, что APK в Assets →
   **Publish release**. В этот момент создастся тег и релиз станет неизменяемым.

## Чего не делать

- Не публиковать релиз до того, как CI догрузил APK (иначе тег сгорит и
  придётся поднимать patch-версию).
- Не переиспользовать имена старых тегов.
- Не запускать «Publish» из черновика до конца CI по той же причине.

## Подпись

APK подписывается в CI: постоянным ключом из секретов
`ANDROID_KEYSTORE_BASE64`/`ANDROID_KEYSTORE_PASSWORD`, если они заданы;
иначе одноразовым ключом раннера — тогда обновление поверх старой версии
может не встать, и игру придётся переустановить с потерей локальных данных.
