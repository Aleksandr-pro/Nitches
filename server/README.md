# Nitches — игровой сервер (Cloudflare)

Аккаунты, база игроков, ежедневные задания, экономика, отзывы, таблица
лидеров и мультиплеерные комнаты свободной езды для игры **Nitches**.
Один Worker + база D1 + Durable Object на комнату. Игра работает и без
сервера (гостевой офлайн-режим) — онлайн включается адресом сервера.

## Деплой с телефона через GitHub (без компьютера) — рекомендуемый способ

В репозитории есть готовый GitHub Actions воркфлоу
**«Deploy Nitches Server (Cloudflare)»**: он сам создаст базу игроков D1,
применит схему таблиц и задеплоит Worker. От вас нужны только два
секрета и одна кнопка — всё делается в браузере телефона.

1. **Токен Cloudflare:** dash.cloudflare.com → меню профиля →
   **My Profile → API Tokens → Create Token** → шаблон
   **«Edit Cloudflare Workers»** → Continue to summary → Create Token →
   скопируйте токен (он показывается один раз).
2. **Account ID:** откройте в дашборде **Workers & Pages** и посмотрите в
   адресную строку: `dash.cloudflare.com/<ВОТ_ЭТО_И_ЕСТЬ_ACCOUNT_ID>/workers-and-pages`.
3. **Секреты в GitHub:** репозиторий → **Settings → Secrets and variables →
   Actions → New repository secret**, добавьте два секрета:
   - `CLOUDFLARE_API_TOKEN` — токен из шага 1;
   - `CLOUDFLARE_ACCOUNT_ID` — ID из шага 2.
4. **Запуск:** вкладка **Actions → «Deploy Nitches Server (Cloudflare)» →
   Run workflow**. Через минуту-другую откройте завершённый запуск —
   в его **Summary** будет адрес сервера вида
   `https://Nitches-server.<ваш-поддомен>.workers.dev`.
5. **В игре:** вкладка **«Онлайн»** → вставить адрес сервера →
   **Регистрация**. Регистрируйтесь первым: первый игрок сервера
   автоматически становится разработчиком с админ-панелью.

Повторный запуск воркфлоу безопасен: существующая база находится по
имени и не пересоздаётся, схема применяется идемпотентно
(`CREATE TABLE IF NOT EXISTS`), Worker просто обновляется.

## Деплой с компьютера вручную (один раз, ~5 минут)

Нужны Node.js 18+ и аккаунт Cloudflare.

```bash
cd server
npm install          # поставит wrangler локально
npx wrangler login   # откроется браузер, войдите в свой Cloudflare

# 1) Создать базу игроков и вставить её id в wrangler.toml
npx wrangler d1 create nitches-db
#    -> скопируйте database_id в wrangler.toml (REPLACE_WITH_YOUR_D1_ID)

# 2) Создать таблицы
npx wrangler d1 execute nitches-db --remote --file=schema.sql

# 3) Задеплоить
npx wrangler deploy
#    -> получите адрес вида https://nitches-server.<ваш-поддомен>.workers.dev
```

Затем в игре: вкладка **«Онлайн» → Адрес сервера** → вставить этот адрес →
**Регистрация**.

> ⭐ **Первый зарегистрированный игрок автоматически становится
> разработчиком (роль `admin`)** и получает админ-панель во вкладке
> «Онлайн»: статистика сервера, список игроков, выдача CR, отзывы.
> Регистрируйтесь первым сразу после деплоя!

## Если план Cloudflare без Durable Objects

Удалите из `wrangler.toml` блоки `[[durable_objects.bindings]]` и
`[[migrations]]`. Всё остальное (аккаунты, задания, экономика, лидеры,
присутствие) продолжит работать; мультиплеерные комнаты ответят
«multiplayer is not configured».

## Локальная проверка без деплоя

```bash
npx wrangler d1 execute nitches-db --local --file=schema.sql
npx wrangler dev --local --port 8787
curl http://127.0.0.1:8787/
curl -X POST http://127.0.0.1:8787/api/register \
  -H 'content-type: application/json' \
  -d '{"username":"Dev","password":"secret123"}'
```

## Как устроено

| Часть | Где |
|---|---|
| API и роутер | `src/index.js` |
| Таблицы (users, sessions, profiles, quest_*, feedback, presence) | `schema.sql` |
| Пароли | PBKDF2-SHA256, 100 000 итераций, соль на пользователя |
| Сессии | непрозрачные токены в D1, 30 дней, отзываются логаутом |
| Ежедневные задания | 10 из пула 14, выбор детерминирован датой (UTC) + id игрока; прогресс хранит максимум, награда выдаётся один раз |
| Мультиплеер | WebSocket-комната на мир (Durable Object): ретрансляция позиций машин ~10 Гц; позиции в базу не пишутся |
| Политика конфиденциальности | `GET /privacy` на самом Worker + `docs/PRIVACY.md` в репозитории |

## Безопасность в тестовой версии (честно)

* Клиент присылает прогресс заданий и снимок экономики; сервер проверяет
  типы/диапазоны и однократность наград, но полноценной античит-проверки
  физики нет — для закрытого теста достаточно, для публичного релиза
  понадобится серверная валидация заездов.
* Токен мультиплеера передаётся в query-параметре WebSocket (ограничение
  WebSocket в Godot) — соединение при этом шифруется (wss).
